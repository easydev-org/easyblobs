revert: back to the plain easysetup action; both workarounds are obsolete

The hand-written install (sudo prepare + sudo install, 41 lines) existed only
to work around two upstream defects:

  checksum parser   63a865ce  could not read a bare digest, so every install
                              failed with "published checksum is empty"
  tarball pollution 39f52c02  the chroot check copied base and glibc into
                              $STAGE/nix/store, so a 3-path setup shipped 11 and
                              an unprivileged install wrote into store paths the
                              same tarball had created read-only

Both are fixed. Re-measured here without sudo, from a clean store:

  prepare        -> /nix and /nix/store drwxrwxrwx root root
  install go     -> rc=0, "installed: base-2.44 go-1.27.3"
  /nix/store     -> 12 paths: go plus its real deps (libgcc, libidn2, tzdata,
                    iana-etc ...), not the polluted set
  runner runs go -> go version go1.27.3

So the workaround no longer buys anything, and it costs: 41 lines of YAML that
mirror the action's internals and would have to be kept in step with them.

Worth recording that my diagnosis was half right - the symptom was permissions,
but the cause was a mis-packed tarball, not a store that legitimately held
root-owned dependencies. Upstream fixed the data; the permission error went
away with it.
