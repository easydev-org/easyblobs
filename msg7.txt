fix(npm): apply a whole-packument PUT to every version, not just one

The expanded npm suite found this: `npm deprecate @scope/x@1.0.0` answered 201
and the packument never showed the flag.

Two things had to be separated. The /deprecate endpoint is fine - a hand-written
PUT to it lands the flag and it reads back. But npm 11 does not use it. It reads
the packument with ?write=true and PUTs the WHOLE document back to /<pkg>, with
every version in it and no _attachments:

  npm http fetch GET 200 /artifacts/npm/@scope%2fname?write=true
  npm http fetch PUT 201 /artifacts/npm/@scope%2fname

publish() walked that map, kept ONE version and broke:

  for k, v := range vs { version = k; pkgJSON = v; break }
  s.storeVersion(ctx, pkgName, version, tarball, pkgJSON, "push")

So on a package with 1.0.0 and 2.0.0 it recorded a single version and dropped the
flag, which lives on the version being deprecated. Observed in the packument:
versions became "\u2039empty\u203a,1.0.0,2.0.0" - a nameless entry from the walked map.

Now every version is applied:

  * with _attachments  -> stored as a publish, per version
  * without            -> applied as a metadata update to the version that is
                          already there, so a deprecate cannot replace a good
                          tarball with nothing
  * an empty version key is skipped rather than recorded
  * if nothing could be applied the request is a 400, not a silent 201

Two regression tests: one asserts both versions survive a deprecate with the flag
on the right one, the other asserts a metadata-only PUT leaves the tarball
byte-identical.

Not compiled locally - ci.yml runs vet/test/build over every workspace module,
which is where this gets checked.
